# 运行与运维

## 三种「在看」的证据，别只看一种

| 证据 | 位置 | 能证明什么 | 不能证明什么 |
| --- | --- | --- | --- |
| 心跳 | `state/health.json` 的 `time` | 进程活着、在循环 | 任务是否成功 |
| 台账 | `state/ledger.sqlite3` | 任务状态与核验结果 | 事实是否正确 |
| 看板 | `<vault>/01-看板/第二大脑处理进度.md` | 人可读的进度与最近结果 | 全量覆盖率 |

日志在 `state/worker.jsonl`，已脱敏，JSON Lines。

## 读懂看板

| 字段 | 含义 |
| --- | --- |
| 已建立重点窗口 | 已经被选择过的会话数（不代表已精读全文） |
| 已采集待选 | 已落库但还没被选择器处理的会话数 |
| 选取正文 / 原证据 | 实际送进模型的字符量 / 对应原始消息字符量 |
| 尚未首次扫描 | 还没读过任何内容的历史会话 |
| 采用开头/近况抽样 | 中间原文未精读的会话数（缺口可在台账 `focus_sampling:*` 查到） |
| 过去 24 小时提交 | 已用/总预算，含重试 |
| 有实际核验写入的批次 | 真的写了笔记并通过回读与引文核对 |
| 现有笔记已核验 | 内容已存在，确认覆盖后跳过（不是失败） |
| 重点筛选未提取 | 窗口内没有值得沉淀的信息（**不等于**完整审阅过） |
| 失败保留 | 会按退避重试；超过次数后停在 failed |

「还没跑完」和「失败」是两种状态。历史回补是长期任务，用批次成功率与失败原因判断健康度，
不要用「剩余会话数 ÷ 每日预算」推算完成日期。

## 暂停与恢复

```jsonc
// 暂停新任务，但仍核验已在处理中的任务
"dispatch": false

// 完全停摆（含采集）
"enabled": false
```

改完即生效，无需重启：主循环每 15 秒重读配置。恢复时把值改回去即可，队列保持原样。

想立刻停进程（例如要改代码）：

```powershell
# 只终止命令行确实指向本项目 worker.py 的进程，避免误杀别的 Python
Get-CimInstance Win32_Process -Filter "Name like 'python%'" |
  Where-Object { $_.CommandLine -like '*second-brain*worker.py*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

插件会在下一轮（≤60 秒）重新拉起。

## 回滚

1. `"dispatch": false`，等当前任务结束或超时核验完成。
2. 停止进程（上面的命令）。
3. 备份 `second-brain/` 与 `state/`，再替换代码/配置。
4. 重启进程，确认心跳与台账计数未异常跳变。
5. 笔记不需要回滚：所有批次都记录了路径与来源，需要纠正就按来源改笔记，而不是批量删。

强烈建议把笔记库纳入 git：程序每次写入都会改文件，git 能给出精确的 before/after。

## 常见故障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 插件日志 `failed to load plugin` | 插件 API 形态不匹配（应为 `export default { id, setup }`） | 升级客户端或改用对应版本的插件 |
| `health.json` 时间不更新 | 进程退出 / Python 不可用 | 手动跑 `start-worker.ps1` 看报错；设置 `SECOND_BRAIN_PYTHON` |
| 心跳正常但 `written_verified` 长期为 0 | 整理会话被人工消息占用，或模型无工具能力 | 看会话最后一条用户消息；换有工具能力的模型 |
| 报 `free` 模型被拒绝 | 桌面端禁用免费模型 | 程序会自动跳过 `-free`；确认模型目录里有非免费可用模型 |
| MCP 报 `ECONNRESET` / 超时 | 共用 HTTP 网关不稳 | 配置 `mcp_command` 给笔记库目录单独起 stdio；或重启网关并做一次真实工具调用验证 |
| 失败原因 `receipt does not cover the complete refs` | 整理者只看了部分窗口却声称处理完 | 正常拦截，会自动重试；连续出现说明批次太大，调小 `focus_batch_sources` |
| 失败原因包含「无成功写入调用」 | 模型只读了没写，或写入报错 | 同上；必要时把该来源拆小、换模型 |
| `database is locked` | 有两个进程在抢 | 文件锁失效或被绕过（例如复制到别处同时启动），只保留一个 |
| 集成会话一直 `processing` | 任务提示被人工消息覆盖 | 超时逻辑只在最后一条用户消息是本次任务时中断；否则等它自然结束，或人工处理 |

## 预算突然用满

预算是滚动 24 小时，不是自然日，所以会逐笔释放。看板里有「预算最早释放」时间。
若想放宽，改 `daily_job_limit`；想省钱，先降低 `focus_batch_sources` / `focus_window_chars`，
不要靠减少核验来提速——那等于放弃唯一的质量保证。

## 备份什么

| 路径 | 内容 |
| --- | --- |
| `second-brain/`（代码外） | `config.json`、`state/`（含台账、日志、健康） |
| 笔记库 | 笔记与看板；建议 git |
| `second-brain/backups/` | 升级前的代码/配置快照（自行保留） |

台账可以用 SQLite 的一致性备份，不要直接复制 WAL 中的库：

```python
import sqlite3
src = sqlite3.connect('state/ledger.sqlite3')
dst = sqlite3.connect('backup/ledger.sqlite3')
src.backup(dst)
```
