# 笔记库规则

程序只负责「把重要信息带进来」，笔记库本身需要一套规则，否则跨会话检索会读到互相矛盾的内容。
`docs/vault/` 下三份文件可直接使用。

## 目录约定

```
00-入口/
  第二大脑.md        总入口：先读这里，再决定读哪 1–3 篇
  AI-整理规则.md     写入方的规则（整理会话与人工维护都遵守）
  首页.md            可选：人读的导航
01-看板/             程序自动写进度看板
10-项目/             以项目为单位的当前状态与历史
20-资产/             服务器、设备、域名等资产事实
30-链路/             依赖与调用关系
40-运维/             操作记录、故障记录
50-账号/             账户与订阅状态
50-账号/凭据/        敏感值，只允许该目录出现，禁止整目录读取
60-成本/
70-个人/             目标、偏好、生活与长期关注
80-知识/             可复用方法与验证过的经验
85-想法/             尚未承诺的想法（不是任务）
90-模板/             节点模板
Inbox/               拿不准时的暂存
```

不要求一次建全。程序按主题选路径，没有的目录会在需要时出现。

## 写入规则（摘要）

1. **先读后写。** 先读 `00-入口/第二大脑.md` 与规则，再按对象名/别名检索；有关联笔记就合并，不要平行新建。
2. **一个事实一个主节点。** 同一对象只保留一个权威笔记，其余通过双链引用，避免同一状态散落多处。
3. **每个事实都带来源。** `source_session` + `source_messages`（原始消息 ID，必要时标 `#partN/total`）、
   `recorded_at`、`occurred_at`、`verified_at`、`certainty`。
4. **区分三类内容。** 用户明确说的 / 工具或文件证实的 / 助手推断的。助手说「已完成」不是证据。
5. **想法不是承诺。** 提出、考虑、设想的内容标为候选，除非用户明确决定。
6. **冲突保留时间线。** 新旧矛盾不要覆盖，写清各自日期与证据，标出当前采信哪一条及原因。
7. **索引只放链接与一句摘要。** 会频繁变化的状态放在主节点，索引不复制。
8. **凭据只进 `50-账号/凭据/`，** 且不在普通摘要、索引、日志里复述值。
9. **写完回读。** 以实际读回的内容为准，不以「我写好了」为准。
10. **没有新信息就不写。** 重复时指出已有笔记路径与依据；宁可 `no_value`，不要造噪声。

## 检索规则（业务会话侧）

写进笔记库根目录 `AGENTS.md` 或你的全局规则，让所有业务会话都知道入口：

- 新任务涉及既往决策、进度、已知问题、长期目标或个人偏好时，先检索再回答。
- 先读 `00-入口/第二大脑.md` 或对应索引，再读最相关 1–3 篇；不做全库扫描。
- 关键词无命中就换别名：旧名、目录名、设备型号、关联主题、英文/缩写。
- 明确区分「笔记记录的日期」与「现在的状态」；服务健康、账号可用性等实时事实必须现场核验。
- 不注入与当前问题无关的个人记忆，不读整个凭据目录。
- 工具不可用就说明记忆未核验，不要编造「我记得」。

## 节点模板

`docs/vault/节点模板.md` 给出推荐 frontmatter：

```yaml
---
type: project | asset | knowledge | person | idea | operation
status: 进行中 | 已完成 | 已废弃 | 卡住 | 想法
updated: 2026-01-01
aliases: [别名, 旧名]
---
```

正文建议包含：当前结论、关键事实（逐条带来源）、时间线、未决问题、关联链接。
来源字段示例：

```markdown
> 来源：会话 `ses_xxx`，消息 `msg_a`、`msg_b#part1/2`；记录于 2026-11-01。
```

## 为什么值得这么麻烦

跨会话记忆的价值不在「存下来」，而在**以后能放心用**。
带来源、带日期、带确定性的笔记，才允许你在半年后直接据它做决定；
不带这些的笔记只会变成又一份需要重新核实的聊天记录。
