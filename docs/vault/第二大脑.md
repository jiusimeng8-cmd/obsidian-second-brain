# 第二大脑

这里保存用户跨项目和日常会话中有长期价值的信息。覆盖工作、项目、生活、学习、目标、明确偏好和想法；聊天仍按原来的项目与事情隔离。

## 从问题进入

| 话题 | 入口 | 主笔记位置 |
| --- | --- | --- |
| 项目与工作进度 | [[AI-业务索引]] | `10-项目/` |
| 设备、服务器与故障 | [[AI读取入口]] | `20-资产/`、`40-运维/` |
| 目标、生活领域、明确偏好 | [[个人与生活索引]] | `70-个人/` |

| 收集是否真正完成 | [[第二大脑处理进度]] | `01-看板/`（台账自动生成） |

先按对象名称、旧名、目录、设备型号或主题检索，再读最相关的1–3篇。无命中时扩展别名。只引用当前问题需要的信息，不把全部生活记忆加入技术讨论。涉及生产状态要重新现场核验。

## 长期记忆怎么记录

- 一个对象一个主节点，保存名称和 aliases；模糊同名保留区分。
- 每条事实记录来源会话、消息范围、记录时间、发生/核验时间和确认程度。
- 区分用户明确陈述、工具验证、助手建议和推断；助手自称完成不是证据。
- 想法不自动变成待办；用户明确决定才升级。进度和待办留在所属对象主笔记。
- 新旧结论矛盾时保留时间与来源，标注历史变更或待核验冲突。索引只路由，避免抄写易变状态。
- 有实质内容但未验证，可以注明“待确认”；不强制每次生成笔记。
- 自动处理不读取凭据目录、不复制凭据值，不推断未表达的敏感属性。

## 自动工作与边界

收集器采用重要记忆优先模式：历史首次抽取开头30条和最新最多200条消息，已采集历史同时筛选中途明确决定；每来源保留约6000字符重点窗口，最多12个短会话合批、总预算48000字符。中间未读及普通过程明确略过、可按来源回查，不承诺完整精读。已结束且空闲60秒的新增消息优先处理。知识维护者只有一个活跃入口：`OBS 记忆整理`；人工任务未结束时自动派发暂停。

处理台账在本机 `.config/opencode/second-brain/state/ledger.sqlite3`，独立于软件原数据库。真实笔记回读并核对来源后才标记核验写入/重复；窗口无重要信息单独标记“重点筛选无新增”，不等于整段原文已审阅。旧细碎队列逐批映射为已替代，证据不删除，失败保留重试。历史归档会话也可参与重点整理；其他客户端尚未接入。

用户提出“不要记住/不要记录”时，收集器保守排除整个来源会话；不会据此删除之前已经存在的笔记。需要细粒度删除时明确指出对象和范围，由人工确认后处理。

模型按实际目录匹配 DeepSeek Flash 家族，失败冷却并有限重试；未出现在模型目录的新型号无法凭空发现。工具调用和回读验证成功才表示该任务可用。
