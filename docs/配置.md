# 配置

配置文件：`second-brain/config.json`（从仓库根目录的 `config.example.json` 复制）。
进程每次循环都会重新读取，改完不需要重启；`enabled: false` 会停止采集和派发。

```json
{
  "enabled": true,
  "dispatch": false,
  "processing_mode": "focus",
  "vault": "/absolute/path/to/vault",
  "title": "OBS 记忆整理"
}
```

## 开关

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 总开关。`false` 时既不采集也不派发，进程保活但空转。 |
| `dispatch` | `false` | 是否允许**新**任务投递。关闭时仍会核验已在处理中的任务。首次部署建议先 `false` 观察采集，再打开。 |
| `validation_only` | `false` | 只处理 `validation_sessions` 里的会话，且每个来源只放行一个已核验批次。用于试点验收。 |
| `validation_sessions` | `[]` | 试点会话 ID 列表（`ses_...`）。 |
| `exclude_sessions` | `[]` | 永不采集的会话 ID。也可以在会话里明确说「不要记住这件事」，采集器会把整个来源排除。 |

## 路径与身份

| 键 | 说明 |
| --- | --- |
| `vault` | 笔记库绝对路径。所有笔记读写都被限制在这个目录内，凭据目录、`.trash`、隐藏目录除外。 |
| `title` | 整理会话的标题。列表里始终只有一个该标题的活跃会话，超长轮换时旧会话改名并归档。 |

## 节奏

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `quiet_seconds` | `60` | 会话最后一条消息结束多久后才冻结这一段，避免边聊边抓。 |
| `poll_seconds` | `15` | 主循环间隔。 |
| `job_timeout_seconds` | `600` | 单个任务超时。超时只在「最后一条用户消息正是本次自动任务」且收件箱为空时才会中断整理会话；人工消息永不打断。 |
| `max_attempts` | `3` | 单任务最大尝试次数，超过后保留为 `failed` 不再自动重试。 |
| `daily_job_limit` | `100` | 滚动 24 小时的模型提交上限，**含重试与旧任务**。所有调用共享这一个预算。 |

## 选择与批次（重点模式）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `processing_mode` | `focus` | `focus` = 重要窗口抽样；`full` = 旧的全量分块模式（约 18000 字符一块，慢且贵，不建议）。 |
| `focus_window_chars` | `6000` | 每个来源在一批里最多提供的字符数。 |
| `focus_batch_sources` | `12` | 一批最多合并多少个来源。 |
| `focus_batch_chars` | `48000` | 一批的字符总量上限（含每源约 160 字符的表头）。 |
| `focus_mix_small_batches` | `true` | 同目录来源凑不满时，允许跨目录补齐，避免为稀疏来源单独消耗一次调用。 |
| `chunk_chars` | `18000` | 仅 `full` 模式使用。 |
| `rotate_messages` | `40` | 整理会话累计多少条有效发言（用户 + 有正文的最终助手回复）后轮换：归档旧会话并新建同名的干净会话。 |

## 模型

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `preferred_family` | `deepseek.*flash` | 模型族正则，命中优先。改成你实际可用的族名即可，不必写死版本。 |
| `preferred_providers` | `[]` | 供应商优先级顺序，例如 `["my-provider", "backup-provider"]`。 |

不要在这里写模型 ID：模型目录会变，写死会失效。程序每次从 `/api/model` 现场挑选并缓存成功结果。

## MCP（可选）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `mcp_command` | `null` | 给笔记库目录单独指定 stdio MCP 启动命令。`null` 表示完全不动 MCP 配置。 |
| `mcp_server` | `"obsidian"` | 要覆盖的 MCP 服务名。 |

若共用 HTTP MCP 网关在高负载下报 `ECONNRESET`，可以只给笔记库目录换成本地 stdio：

```json
{
  "mcp_command": ["cmd.exe", "/d", "/c", "npx.cmd", "--yes", "@bitbonsai/mcpvault@0.16.0", "{vault}"],
  "mcp_server": "obsidian"
}
```

`{vault}` 会被替换为 `vault` 配置值。这个覆盖是运行时的、只对笔记库目录生效，重启客户端后由程序在下次派发前重新应用。

## 环境变量

| 变量 | 作用 |
| --- | --- |
| `SECOND_BRAIN_ROOT` | 插件查找代码目录的位置（默认 `~/.config/opencode/second-brain`）。 |
| `SECOND_BRAIN_PYTHON` | 指定 Python 解释器（`pythonw.exe` / `python3`）。 |
| `SECOND_BRAIN_SETTINGS` | 指定客户端设置文件路径（默认 `~/.config/openchamber/settings.json`），用于读取本机端口与本地客户端令牌。 |

## 推荐起点

- 第一次部署：`enabled: true`、`dispatch: false`、`validation_only: true`，挑 3 个不同目录的会话做试点。
- 试点通过（有实际写入、回读、来源可追）：`validation_only: false` 打开全量。
- 长期运行：`daily_job_limit` 按你的成本耐受度设，观察看板里的「平均批次耗时」和失败率再调整。
